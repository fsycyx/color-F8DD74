# 餐衡 FoodLens

面向现代人日常饮食与生活方式记录的 AI 健康决策助手参赛原型。项目当前为可独立运行的 Vue 前端，完整演示菜单识别、决策比较、健康记录、趋势洞察和带引用问答流程。

## 运行

```bash
pnpm install
pnpm run dev
```

浏览器访问 `http://localhost:5173`。

构建与测试：

```bash
pnpm run build
pnpm run test
```

## 代码规范

- 使用 TypeScript 严格模式，业务数据通过 `src/types.ts` 中的接口约束。
- 使用 2 个空格缩进、UTF-8、LF 换行；基础编辑器规则见 `.editorconfig`。
- 中文注释用于解释模块职责、业务边界、异步流程和资源清理，不重复描述直观代码。
- 页面负责交互与展示，跨页面状态集中在 Pinia，AI/OCR 调用统一通过服务适配层。
- 上传图片的本地预览地址、定时器、图表实例和全局监听必须在组件卸载时释放。
- 涉及健康数据的计算结果使用区间和来源说明；异常时明确降级，不伪造模型结果。

## 已实现模块

- 今日健康驾驶舱：饮水、睡眠、活动、蔬菜状态、行动提醒和健康时间线。
- 智能点餐：图片上传、模拟 OCR、低置信结果校正、三方案对比、自然语言换菜重算和餐食记录。
- 健康记录：饮水、睡眠、活动、久坐、情绪与饥饿感。
- 食品标签：图片上传、单位/份数核对、营养信息与过敏原风险提示。
- 趋势洞察：七日可切换图表、只基于已有记录的关联观察和下周行动。
- AI 问答：异步问答、资料引用、证据不足拒答和医疗边界。
- 设置与隐私：偏好、提醒开关、数据导出入口、本地数据二次确认删除与健康边界。

## 数据与 AI 边界

当前 `src/services/mockApi.ts` 是服务适配层，使用本地演示数据和延迟模拟 OCR、餐食规划与问答。它不会上传用户图片，也不会进行真实医学或营养评估。营养数据均以估算范围表达。

接入真实后端时，保持现有函数签名，将以下函数替换为 HTTP/SSE 请求即可：

- `recognizeMenu()` → `POST /api/menu/analyze`
- `buildPlans()` → `POST /api/meal/plans`
- `askHealthAssistant()` → `POST /api/assistant/chat` 或 SSE 流

API 密钥必须只保存在后端。前端的 `VITE_` 环境变量会暴露给浏览器，禁止存储密钥。

推荐后端继续采用 FastAPI + Pydantic，先做单体服务；数据库可使用 PostgreSQL + pgvector。疾病饮食、孕产期、未成年人、进食障碍、用药和急症请求应由后端安全规则优先拦截，不能只依赖模型提示词。

## 参赛说明

本项目只提供普通成年人的一般健康信息，不进行医疗诊断、治疗、疾病风险预测或精准营养承诺。正式部署还应增加服务端鉴权、上传文件校验、速率限制、日志脱敏、隐私协议和模型安全评测。
